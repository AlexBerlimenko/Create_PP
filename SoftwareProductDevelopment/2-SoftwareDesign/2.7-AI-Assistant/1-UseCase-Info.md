# Рекомендації щодо побудови UML Use Case-діаграм

## Основні принципи:
1. **Актори**:
   - Зацікавлені особи з опису бізнес-вимог
   - Віртуальні актори, пов'язані з роботою програмного продукту
   - Зовнішні інформаційні сервіси зі своїм API

2. **Прецеденти**:
   - Розташовуються всередині прямокутника системи
   - Назва прецеденту відображає конкретну задачу
   - Кожен прецедент має надавати користувачу значимий результат

3. **Зв'язки**:
   - **Узагальнення** між акторами - для уникнення дублювання прецедентів
   - **Include-зв'язки** - обов'язкові допоміжні прецеденти
   - **Extend-зв'язки** - альтернативні дії

4. **Межа системи**:
   - Прямокутник навколо всіх прецедентів
   - Актори розташовуються зовні

## Правила якості:
- Кожен прецедент має бути атомарним
- Назви прецедентів починаються з дієслова
- Уникати занадто деталізованих прецедентів
- Забезпечити логічну повноту діаграми
