# Рекомендації щодо проєктування прототипу програмних класів

## Основні принципи трансформації концептуальних класів у програмні:

1. **Атрибути класів:**
   - Типи даних: цілий (int), символьний (string), дробовий (float)
   - Типи видимості: публічний (+), захищений (#), приватний (-)
   - Захищені атрибути для доступу в межах класу та класів-нащадків

2. **Зв'язки між класами:**
   - Для зв'язків з кратністю "one" створювати атрибути зі складним типом
   - Для зв'язків з кратністю "many" - колекції екземплярів класів
   - Назва атрибуту визначається назвою зв'язку

3. **Методи класів:**
   - Агломовні назви, що враховують комбінацію слів з назвою атрибуту та дії
   - Не обов'язково створювати методи get/set для всіх атрибутів
   - Методи повинні відповідати функціональним вимогам

4. **Обмеження:**
   - Не використовувати шаблони проектування, що створюють штучні класи
   - Зберігати семантичні зв'язки між концептуальними класами
   - Відповідати функціональним вимогам ПП

## Приклади прототипів методів:
- `розрахуватиІМТ()` - для класу ДаніПроЗдоров'я
- `сформуватиПланХарчування()` - для класу ПланХарчування
- `оцінитиСамоповагу()` - для класу Самоповага
